# Accessibility 设计准则

> "如果一个视障用户不能独立完成任务，这不是 demo，是壁画。"

## 核心原则

1. **任何信息都必须有非视觉路径**——视觉是冗余，不是依赖。
2. **单手 + 单点交互**——整屏可点，不需要精确定位。
3. **状态可感知**——每个状态有独特的音效 + 振动模式。
4. **错误必须开口说**——网络断开、权限拒绝、模型超时均 TTS 播报。

## 交互模式

| 输入 | 行为 |
| --- | --- |
| 整屏单击 | 开始/结束聆听 |
| 整屏长按 | 按住说话（松开提交） |
| 唤醒词 "你好小视" | 免触摸激活 |
| 双指任意点击 | 重复上一次 AI 回答 |
| 三指任意点击 | 切换语言（中/英） |

## 状态反馈映射

| State | 颜色 | 振动 | 音效 |
| --- | --- | --- | --- |
| idle | 琥珀 | — | 软"滴" |
| listening | 绿 + 脉冲动画 | 30ms | 上行短音 |
| thinking | 黄 | 20-40-20 | 思考"嗯" |
| speaking | 蓝 | 50ms | — (语音本身) |
| error | 红 | 80×3 | 下行短音 + TTS 错误描述 |

## 屏幕阅读器兼容

- 所有交互元素带 `aria-label`
- 状态变化通过 `aria-live="assertive"` 区域
- 不依赖 hover / focus 视觉指示

## 隐私的可听见性

启动首次："为了帮你看清楚，我需要使用摄像头和麦克风。这些数据仅在我们对话期间使用，结束后立即丢弃。"
